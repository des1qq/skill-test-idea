# Шаблон финального отчёта

Используй именно эту структуру и порядок секций. Не пропускай секции, даже
если по ним мало данных — в этом случае явно пиши "неизвестно" и что нужно
проверить, чтобы это узнать.

```markdown
## Оценка идеи: [название идеи/продукта]

**Итог:** перспективность — X/10
**Рекомендация:** [одна строка — суть вердикта]

### Сильные стороны

- [пункт, с пометкой (факт) или (гипотеза), если не очевидно]
- ...

### Слабые стороны

- [пункт, с пометкой (факт) или (гипотеза)]
- ...

### Главные гипотезы

1. [гипотеза, требующая проверки]
2. ...

### Конкурентные альтернативы

| Альтернатива | Почему выбирают | Как можно отличиться |
| --- | --- | --- |
| [прямой конкурент] | ... | ... |
| [непрямая альтернатива / самостоятельное решение] | ... | ... |
| ["ничего не делать"] | ... | ... |

### Баллы по критериям

| Критерий | Балл | Основание |
| --- | --- | --- |
| Сила проблемы | X/10 | (факт/гипотеза) ... |
| Платёжеспособность аудитории | X/10 | ... |
| Конкуренция | X/10 | ... |
| Доступность первых клиентов | X/10 | ... |
| Сложность реализации | X/10 | ... |
| Потенциальная маржинальность | X/10 | ... |
| Регуляторные и операционные риски | X/10 | ... |

### Что проверить первым

1. [конкретное, выполнимое действие с ожидаемым сигналом успеха/провала]
2. ...

### Вердикт

**[Запускать / Изменить / Протестировать / Отказаться].** [1–3 предложения,
объясняющие решение через ключевые баллы и риски, без расплывчатых
"хорошо/плохо" формулировок.]
```

## Пример (для калибровки тона и глубины — не копировать содержание)

```markdown
## Оценка идеи: сервис планирования ремонта квартиры

**Итог:** перспективность — 7/10
**Рекомендация:** тестировать через узкий MVP для владельцев новостроек.

### Сильные стороны

- проблема понятна и дорого обходится клиенту (факт: средний бюджет ремонта
  высок, ошибки планирования увеличивают расходы);
- пользователи уже тратят деньги на похожие решения (факт: рынок услуг
  дизайнеров и прорабов существует);
- можно начать с одного сегмента — владельцев квартир без опыта ремонта
  (гипотеза: этот сегмент охотнее платит за снижение риска ошибок).

### Слабые стороны

- высокая конкуренция со стороны дизайнеров и строительных компаний (факт);
- трудно доказать качество результата до покупки (гипотеза);
- потребуется актуальная база цен и материалов (операционный риск).

### Главные гипотезы

1. Люди готовы платить не за "план ремонта", а за снижение риска ошибок.
2. Клиентам важнее смета и контроль подрядчиков, чем красивые визуализации.
3. Первый платный продукт можно продавать за фиксированную сумму.

### Конкурентные альтернативы

| Альтернатива | Почему выбирают | Как можно отличиться |
| --- | --- | --- |
| Дизайнер | Полный комплекс услуг | Дешевле и быстрее |
| YouTube и статьи | Бесплатно | Персональный план |
| Прораб | Практическая помощь | Прозрачная смета и контроль |
| Приложения | Удобство | Локальные цены и подрядчики |

### Что проверить первым

1. Провести 10–15 интервью с владельцами квартир.
2. Сделать лендинг с одним конкретным предложением.
3. Запустить рекламу на узкий сегмент.
4. Проверить, готовы ли люди оставить заявку или предоплату.
5. Сравнить три формулировки ценности.

### Вердикт

**Протестировать.** Сначала проверить спрос на услугу "персональная смета +
план ремонта + список ошибок" вручную, не создавая полноценный продукт —
сила проблемы высока, но платёжеспособность и каналы привлечения пока
гипотезы, а не факты.
```
